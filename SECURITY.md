# Security Policy

We take the security of our project seriously. If you discover a security vulnerability, please report it responsibly.

## Reporting Procedure
Please do not report security issues through public issues or pull requests.

**Primary Method:**
Use GitHub's private vulnerability reporting if enabled:
https://github.com/Rafalbanas/weronikarafal/security/advisories/new

**Secondary Method:**
If the above is not available, please contact the maintainer via their public GitHub profile to request a private communication channel. Do not share any sensitive information publicly.

## Report Requirements
When reporting a vulnerability, please include:
- The commit hash associated with the issue.
- A description of the potential impact.
- Minimal synthetic steps to reproduce the issue (do not include real invitation codes, guest data, private media, or secrets).

## Important Notes
- We provide best-effort support for the `main` branch.
- There is no Service Level Agreement (SLA) for security patches.
- Do not perform security testing on production environments; only test locally.
